# Flutter Project Structure

When you create a new Flutter project, you'll see a lot of folders and files. Don't worry! This guide will help you understand what everything is for.

## Complete Project Structure

```
my_flutter_app/
├── android/              # Android-specific code
├── ios/                  # iOS-specific code
├── lib/                  # Your Dart code (main app logic)
├── test/                 # Unit and widget tests
├── web/                  # Web-specific code (if enabled)
├── windows/              # Windows-specific code (if enabled)
├── linux/                # Linux-specific code (if enabled)
├── macos/                # macOS-specific code (if enabled)
├── .dart_tool/           # Build tools (auto-generated)
├── .idea/                # IDE configuration (auto-generated)
├── build/                # Build outputs (auto-generated)
├── .gitignore            # Git ignore rules
├── .metadata             # Flutter project metadata
├── analysis_options.yaml # Dart analyzer settings
├── pubspec.yaml          # Project configuration & dependencies
├── pubspec.lock          # Locked dependency versions
└── README.md             # Project documentation
```

## Key Folders You'll Work With

### 1. lib/
**Most Important!** This is where you write your Dart code.
- Contains `main.dart` - the entry point of your app
- All your screens, widgets, and business logic go here
- You'll spend 90% of your time in this folder

### 2. android/ and ios/
Platform-specific code for Android and iOS
- Usually auto-generated by Flutter
- Modify these when you need native functionality
- Contains app icons, splash screens, permissions

### 3. test/
Write your test cases here
- Unit tests for your functions
- Widget tests for your UI components
- Integration tests for complete flows

### 4. assets/ (You create this)
Store your images, fonts, and other files
- Not created by default - you add it when needed
- Must be declared in `pubspec.yaml`

## Important Files

| File | Purpose |
|------|---------|
| `pubspec.yaml` | Configuration file - dependencies, assets, app info |
| `main.dart` | Entry point where your app starts |
| `analysis_options.yaml` | Code quality and linting rules |
| `.gitignore` | Files to exclude from version control |

## Folders to Ignore (Auto-Generated)

These are created automatically - **don't edit them manually**:
- `.dart_tool/`
- `build/`
- `.idea/` or `.vscode/`

## Best Practices

1. **Keep lib/ organized**: Create subfolders like `screens/`, `widgets/`, `models/`, `services/`
2. **Use meaningful names**: `user_profile_screen.dart` is better than `screen1.dart`
3. **Don't commit build files**: Make sure `.gitignore` excludes auto-generated folders
4. **Version control**: Always commit `pubspec.lock` to ensure consistent builds

## Quick Tips for Beginners

- Start by exploring `lib/main.dart` - it's simple and shows the app structure
- Don't worry about platform folders (android/ios) yet - Flutter handles them
- Focus on learning Dart and building widgets in the `lib/` folder
- Use hot reload (press 'r' in terminal or click in IDE) to see changes instantly
